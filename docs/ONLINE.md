# 飞行中通信与规划：第一版

原来的 `run-fast.cmd` 仍然运行起飞前统一规划的快速版。这一版使用独立入口 `run-online.cmd`，目标先验证飞行中协作过程，不以超过原快速版为验收标准。

2026-10-19 的两次原仿真实测均达到 100% 覆盖并通过规则与实际运动检查，正常运行 144.656 秒，含漏消息与暂停接单测试的运行 150.227 秒。详细证据见 [实时协作验证记录](ONLINE_VALIDATION.md)。

## 实际怎样协作

六个 `online_agent.py` 进程分别代表六架无人机，每个只订阅自己的位置、官方障碍点云以及其他飞机的消息，不订阅老师的全队覆盖图，也不直接订阅其他飞机的位置。

每架根据自己的实际位置和向下视野，累计自己看过的格子，随消息发送压缩后的记录。收到其他飞机的记录后，合并成这一轮共同的探索进度。这里使用带少量余量的圆形视野，不从老师统计图中抄探索结果。

每轮包括以下过程：

1. 各自广播自己的位置、已观察区域、已完成和正在执行的任务、已确认路线。
2. 对尚未完成且没有其他飞机正在执行的观察任务报价。报价主要看从当前位置绕障过去需要多久，并稍微偏向能看见更多新区域的位置。没有提前为每架分配整场任务。
3. 六方各自根据收到的同一组报价，算出一致的分工。一架在一轮只接一个观察任务；忙碌的飞机不再接新任务。
4. 获得候选任务的飞机计算自己的短路线，考虑其他飞机已确认的运动及停留位置，必要时绕开或等待。只规划接下来的一个任务，不生成整场完整路线。
5. 六方交换候选路线，各自检查可同时执行的安全子集，对同一批消息和结果给出摘要确认。
6. 六个确认全部一致且未过执行时限，才下发这一轮的新路线。缺消息、确认不一致或计算超时，这轮取消，已经确认的路线继续到安全停靠点。

任务目标位置由已知地图生成；任务归属、先后顺序和短路线在飞行中逐轮确定。每次到点后，根据新进度重新竞争剩余任务。

## 保留的集中功能

`online_flight.py` 负责启动、分轮计时、核对六份确认和独立验收，不计算报价、不选择任务、不生成路线。实际控制指令仍由一个 C++ 执行进程分别发送，以保持 100 Hz 输出；任务决策发生在六个独立进程中。

因此这是“六方消息协商 + 统一时钟和执行服务”的原型，不能宣称完全没有中心。协议要求所有六方在线并能及时互通；缺少一个参与者就暂缓新任务，尚未实现断网分组、故障成员移除或任意延迟下的共识保证。

官方完整障碍地图继续用于避障。这里改变的是飞行中的任务协作，没有额外实现未知地图的发现、建图或传感器遮挡。

## 飞行方式与限制

第一版使用平稳的起停轨迹，在观察任务及绕障转角处可能停靠；不会为了每轮通信强制让正在飞的飞机停车。已确认路线由 C++ 节点持续执行，计算和通信不会阻塞指令发送。

计划速度 4.5 米/秒、计划加速度 2.2 米/秒平方、高度 7.5 米，原作业上限和仿真配置不变。每段时间仍由包含加速度平方积分的时间与能量代价确定。机间距检查对采样之间的移动留出余量，实际速度、IMU 加速度、高度和距离另外记录。

后续如需提高速度，再将“到点后接下一个任务”升级成提前接续后续路线。不能直接套用原 50 秒版本的成绩。

## 启动

添加 C++ 节点后先重新编译一次：

```bash
bash setup/ros/build_course.sh
bash setup/ros/run_online.sh
```

Windows 可双击仓库根目录的 `run-online.cmd`，发行版名称仍读取 `local-settings.json`。无桌面使用 `COURSE_GUI=0`。

用独立端口验证通信缺失，并让 2 号飞机在第 25—50 秒暂不接新任务：

```bash
COURSE_ROS_PORT=11341 COURSE_ONLINE_DROP_ROUND=20 \
COURSE_ONLINE_PAUSE_UAV=0 COURSE_ONLINE_PAUSE_AT=25 COURSE_ONLINE_PAUSE_FOR=25 \
bash setup/ros/run_online.sh online_fault_check
```

`COURSE_ONLINE_PAUSE_UAV` 是从 0 开始的内部编号，0 对应 uav2；这只限制领取新任务，已有飞行继续正常完成。漏消息测试只故意漏掉某一轮 uav2 的任务报价，不修改原仿真或飞行速度。

## 证据

输出目录为 `experiments/story1/online_results/<运行名称>/`：

- `result.json`：老师计时、覆盖率、实际运动检查、分配次数与取消轮数。
- `messages.json`：真实 ROS 消息记录，包含各自观察进度、报价、路线提议、六方确认和任务领取。
- `rounds.json`：每轮是达成一致还是取消，以及实际接受哪些任务。
- `flight_trace.json`：实际飞行位置。
- `teacher_messages.json`：老师检测输出。
- `peer2.log` 到 `peer7.log`：各自进程的诊断日志。

独立复查：

```bash
source /opt/ros/noetic/setup.bash
python3 experiments/story1/online_protocol.py
python3 experiments/story1/check_online_run.py experiments/story1/online_results/<运行名称>
```

检查重点是：实际飞行中持续领取任务；每次领取对应六份相同确认；已观察信息来自各自飞行并通过消息共享；漏消息那轮没有领取任务；暂停接单期间其他飞机仍在分配剩余任务；老师与实际运动检查均通过。
